# 03 架构与技术选型

> 上游：[02-需求解读.md](02-需求解读.md)。本文件定义**分层架构、目录布局、依赖分层、关键选型与理由**，以及 M0 骨架的落地边界。

## 一、分层架构

```
┌───────────────────────────────────────────────────────────────┐
│  表现层（薄）                                                  │
│  cli/  （argparse，console_scripts 入口）                       │
│  gui/  （PySide6 页签，可选依赖；只渲染引擎结果，零判定逻辑）    │
└────────────────────────┬──────────────────────────────────────┘
                         │ 只调引擎 API（CLI 与 GUI 共用同一编排）
┌────────────────────────▼──────────────────────────────────────┐
│  编排层  engine/pipeline.py                                    │
│  check_card() / check_file() —— 单一编排事实源（单件/批量共用）  │
└────────────────────────┬──────────────────────────────────────┘
┌────────────────────────▼──────────────────────────────────────┐
│  领域层（纯确定性，零第三方依赖）                                │
│  rules/     规则库加载 + status 门控 + 场景门控 + 版本坐标        │
│  mapping/   字段映射引擎（容器键 → 国标字段）                     │
│  parse/     容器解析通路（PNG/JPEG/ISO BMFF → 标识卡，M2）        │
│  engine/    explicit / implicit / integrity 三核验器            │
│  model/     统一中间表示（LabelCard / 判定结果 / 报告对象）       │
└────────────────────────┬──────────────────────────────────────┘
┌────────────────────────▼──────────────────────────────────────┐
│  应用层                                                        │
│  scan/      批量扫描（失败隔离、进度、两轮对账）                 │
│  report/    报告导出（MD / XLSX / CSV）+ 证据链指纹              │
│  benchmark/ 内置基准（零 API，可重复）                          │
└────────────────────────┬──────────────────────────────────────┘
┌────────────────────────▼──────────────────────────────────────┐
│  基础设施层                                                    │
│  paths.py   数据目录定位（源码态 / 冻结态分支）                  │
│  errors.py  异常与退出码语义                                    │
│  rng.py     确定性 RNG（splitmix64）                            │
│  jsonio.py  确定性读写（无时间戳、LF、Decimal 友好）             │
└───────────────────────────────────────────────────────────────┘
                         │
                  data/  冻结数据资产（规则库/映射表/样本真值）
```

**依赖方向只向下**，且 `cli` 模块顶层**禁止 import GUI**（AST 守门测试断言，见 04 §十）——保证
无 GUI 依赖环境（CI 的 `.[dev]` 通路）也能完整跑 CLI 与测试。

## 二、目录布局（仓库根 = 包根 + plan/ + data/）

```
10-13-ai-content-labeling-checker/
├─ plan/                     计划与交接文档（00–06 + HANDOFF-Mx）
├─ data/                     冻结数据资产（台账见 data/README.md）
│  ├─ rules/                 版本化核查规则库（依据 × 版本）
│  ├─ mapping/               元数据字段映射表
│  ├─ truth/                 合成样本 + 真值库（M1 起）
│  └─ knowledge/raw/         官方原文/标准页面快照（M1 起）
├─ src/labelcheck/           核心包（见 §三）
├─ tests/                    测试（全离线，无网络）
├─ tools/                    生成器与运维脚本（gen_rulesets / make_demo_assets / …）
├─ docs/                     技术报告、演示素材（M4-M5 起）
├─ .github/workflows/        CI
├─ pyproject.toml
├─ README.md  LICENSE  .gitignore  .gitattributes
```

**为什么 `src/` 布局**：避免"当前目录恰好有个同名包"导致的假绿；可编辑安装后 `labelcheck.__file__`
指向 `src/`，测试断言对象明确（系列踩坑：`sys.path` 污染导致测错对象）。

## 四、关键选型与理由

| 选项 | 选择 | 理由 / 备选与弃用 |
|---|---|---|
| 语言 | **Python 3.8+** | 与系列一致、本机实测可用（3.8.8）；老解释器上 PySide6/PyInstaller 版本坑已有系列经验（见阶段 6） |
| 包布局 | `src/` 布局 + `pyproject.toml`（setuptools） | 可编辑安装；无 `setup.py`；3.8 兼容写法 |
| 核心依赖 | **零第三方**（纯 stdlib） | NFR-1/NFR-2：确定性、全本地、零 API、可离线基准 |
| CLI | **argparse**（stdlib） | 无需网络、无额外依赖；子命令清晰；退出码可锁 |
| 规则库格式 | **JSON**（不用 YAML） | 零依赖解析、确定性、diff 友好；YAML 需第三方库且易歧义 |
| 报告 xlsx | `openpyxl`（optional extra `report`） | 纯 Python 无编译依赖；缺失时降级为 CSV 并提示（不崩） |
| GUI | **PySide6**（optional extra `gui`） | 与系列一致；本机 3.8 上需锁版本上限（系列实测 6.6.3.1 为 3.8 可解析最高） |
| 打包 | **PyInstaller onedir 双 exe**（optional extra `pkg`） | 双 exe = GUI（`console=False`）+ CLI 控制台（`console=True`），无 Python 机器可脚本化验证 |
| 测试 | **pytest**（dev extra） | 全离线；GUI 用 `importorskip` 声明式跳过 |
| 确定性 RNG | **自研 splitmix64** | stdlib `random` 不承诺跨版本序列一致；生成器必须跨机器逐字节可复现 |
| 图片/音视频解析 | **纯 stdlib 结构解析**（M2 定；不引 Pillow/ffmpeg） | 只要**元数据段**（PNG 块 / JPEG 段 / ISO BMFF box），用 `struct`+`zlib` 足够；结构坏时能**显式降级**，且保住核心层零第三方（D05、D26） |
| LLM | **不使用**（决策记录显式留档） | 领域为纯确定性规则 + 结构化输入，无解析兜底需求；零 API = 结论 100% 可复现 |

## 五、依赖分层（extras）

```toml
[project.optional-dependencies]
dev  = ["pytest", "pyyaml"]        # pyyaml 供 CI workflow 可解析守门测试
report = ["openpyxl"]              # XLSX 导出；缺失降级 CSV
# 旧解释器（3.8）上的重依赖写**上限**（只写下限等于没 pin）：
gui  = ["PySide6<=6.6.3.1; python_version < '3.9'",
        "PySide6>=6.6,<6.8; python_version >= '3.9'"]   # 桌面界面
pkg  = ["pyinstaller>=5.13,<6; python_version < '3.9'",
        "pyinstaller>=6; python_version >= '3.9'"]      # 打包
```

**纪律**：
- 核心 `dependencies = []`（空）——任何核心层引入第三方依赖都属架构违规，测试断言 `src/labelcheck` 中除
  `gui/`、`packaging/`、`report/xlsx` 外的模块不 import 第三方包。
- extras 必须覆盖**运行期与测试期的真实 import**（系列踩坑：TestClient 需 httpx、`File(...)` 需
  python-multipart —— 漏声明是"静默少跑"不是报错）。
- 老解释器（3.8）上的重依赖写**上限**（只写下限等于没 pin）。

## 六、`find_data_dir` 四分支（冻结态失真的唯一防线）

数据定位优先级（**改动属"会打挂测试"的口径变更**）：

1. **显式参数**（CLI `--data-dir`）；
2. **环境变量** `LABELCHECK_DATA_DIR`；
3. **冻结态内嵌**：PyInstaller 6 `sys._MEIPASS/data` → PyInstaller 5 平铺 `exe目录/_internal/data` → `exe目录/data`；
4. **源码态**：从 `__file__` 上溯找含 `data/rules` 的仓库根；再兜底 CWD 上溯。

**验伪要点**：冻结态自检必须断言解析到的数据目录**落在 dist 之内**；若落到仓库 `data/`，说明内嵌数据
"验了个寂寞"（系列实测假结果陷阱）。故干净验证一律在中立目录（`%LOCALAPPDATA%\Temp`）+ `env -i` 下跑。

## 七、跨平台与确定性

- `.gitattributes` `* text=auto eol=lf` + **冻结 fixtures 出现 CR 即大声失败**的守门测试（EOL 门）。
- 生成器落盘一律 `newline="\n"` / `write_bytes`（Python 3.8 无 `Path.write_text(newline=)`，用 `open(...)`）。
- 产物**不带时间戳**；报告头的时间字段由调用方显式传入（基准/测试传固定值）。
- zip 型产物（若后续引入）一律 `ZIP_STORED` + `create_system=0`（跨平台字节冻结）。

## 八、M0 骨架的完成边界（本里程碑做什么 / 不做什么）

**做**：plan 02–06 定稿；`src/labelcheck` 基础设施 + 规则库加载/门控 + 引擎骨架（规则驱动可跑通空规则库）+
CLI 三通路 + 测试全绿 + CI 三矩阵首跑绿 + 台账/索引回写。

**不做（留给后续里程碑）**：真实规则条目（M1，须逐条挂原文核对）、字段映射表内容（M1）、合成样本生成器与
真值库（M1）、批量扫描与对账（M3）、报告导出（M3）、基准 runner（M4）、GUI 与打包（M5，**已落地**）、发布（M6）。

## 九、M5 落地状态（桌面界面与打包）

- **`gui/`**：六页签（单件核验 / 批量扫描 / 两轮对账 / 基准指标 / 规则库与依据 / 关于）全部落地；
  `services.py` 是**唯一引擎调用点**且**零 Qt**（无 PySide6 也能导入，故服务层被普通 pytest 全覆盖）；
  `tabs.py` 用函数体内 `_qt()` 惰性取 Qt 符号（模块可导入，仅构造控件才需 Qt）；
  `main_window.py` 顶层 import PySide6（在 `gui/` 豁免名单内），CLI `gui` 子命令**函数体内**惰性导入它。
  契约与守门见 04 §十二 / §十。
- **`packaging/`**：`build_datas()` 白名单（`rules`/`mapping`/`truth`/`parse`/`samples`/`knowledge`）、
  `assert_ready()` 构建前置检查、`verify_dist()` 冻结态验伪（**数据目录必须落在 dist 之内**）。
  onedir 双 exe（GUI `console=False` + CLI `console=True`）；CLI exe 排除 PySide6/PIL/numpy
  以保住"零 GUI 依赖"属性与体积（实测 GUI ≈158 MB、CLI ≈13 MB）。
- **演示素材**：`tools/make_demo_assets.py` 离屏渲染 `docs/demo/`（截图 + GIF），进 README。

> M0 的规则库刻意**只有 `pending` 条目**（`verified` 为 0）：这既符合"未核对不得生效"纪律，也顺带把
> 门控路径在 M0 就纳入测试覆盖——真实条文核对是 M1 的活。
