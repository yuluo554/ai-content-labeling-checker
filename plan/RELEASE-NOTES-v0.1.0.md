# labelcheck v0.1.0

**AI 生成合成内容标识合规核查器**——以《人工智能生成合成内容标识办法》（国信办通字〔2025〕2 号，
2025-09-01 施行）与强制性国家标准 **GB 45438-2025**《网络安全技术 人工智能生成合成内容标识方法》
为规则源，把**显式标识 + 隐式元数据标识**的合规核验做成**规则化、可批量、留指纹证据**的本地工具
（桌面 exe + CLI 双形态）。**全本地核查、零上传**，不做任何去水印/标识规避。

> 技术报告见 [docs/技术报告.md](https://github.com/yuluo554/ai-content-labeling-checker/blob/main/docs/技术报告.md)。

## 能做什么

- **单件核验**：显式标识**要素级 + 位置级**判定 + 隐式元数据字段级核验，结论逐条挂条款依据；
- **容器解析通路**：PNG / JPEG / MP4 / M4A 的元数据里抽取 AIGC 载荷（GB 45438-2025 附录 E 格式）
  → 同一标识卡；解析不到**显式降级**，绝不臆测；
- **批量扫描**：目录递归 / 清单投喂，失败件隔离（"未判定"≠"违规"）；超大容器安全阀；
- **两轮对账**：新增违规 / 已修复 / 持续违规 / 内容变动（**稳定身份键**配对，非内容指纹）；
- **报告与证据链**：Markdown + CSV + XLSX（逐件逐字段）+ `evidence.json`（每件内容 sha256 +
  报告自身 sha256），产物**逐字节可复现**；
- **桌面界面**：六页签（单件核验 / 批量扫描 / 两轮对账 / 基准指标 / 规则库与依据 / 关于），
  **只渲染引擎结果、零判定逻辑**（与 CLI 结论必然一致）。

## 内置评测基准（可复现的正确性证据）

`labelcheck bench` 一条命令跑三类基准（仓库真实规则库 + 随附算例实测）：

| 基准 | 指标 | 实测 | 达标线 |
|---|---|---|---|
| `fields`（30 例） | 判定准确率 | **100%**（30/30） | 100% |
| `constructed`（34 例） | 检出率 | **100%**（23/23） | ≥ 95% |
| | 误报率 | **0%**（0/11） | 0（硬口径） |
| `diff`（2 场景） | 对账集合一致率 | **100%**（2/2） | 100% |

## 规则库版本化与 status 门控（核心纪律）

规则按 **`依据文件 × 版本`** 组织，每条挂文号/标准号与 `status`：`verified`（已逐条挂原文核对，
可进入判定路径）/ `pending`（待核对，**绝不参与任何判定**）。**未挂原文核对的条目不得落库生效**
——这是"不编造条号、不输出假合规"的工程落点。当前生效规则 **27 条**（国标 25 + 办法独有 2）。

## 退出码（脚本化契约）

| 码 | 含义 |
|---|---|
| `0` | 完成且未发现不合规项 |
| `1` | 完成但**检出不合规**（`scan` 任一件 fail 即 1；`bench` 为"有基准未达标"） |
| `2` | 用法/输入错误 |
| `3` | 环境/依赖错误（数据目录定位失败、规则库损坏） |

## 已知环境问题

- 桌面版为 Windows onedir 形态，无 Python 的机器也可运行；首次启动稍慢（解压内嵌数据）。
- CLI 版**不含 Qt**（体积小、可管道）；桌面版含 Qt（体积大、双击即用）——按需下载。
- 存在界面依赖的安装（源码态）：`pip install -e ".[gui]"`；打包：`pip install -e ".[pkg]"`。
- 解析通路首批载体为 PNG/JPEG/ISO BMFF 的**元数据**；纯文本文件无元数据容器，走人工录入标识卡。

## 限制与免责

- 本工具为**合规辅助**，正式合规认定以监管口径为准；**不提供任何去水印/标识规避功能**。
- 首期范围：《标识办法》+ GB 45438-2025 的文本/图片/音视频标识字段规范。
- 解析盲区：文件解析器读不到渲染后的画面文字/语音 → 解析通路的显式作用域恒为"未观测"（`unknown`）。
