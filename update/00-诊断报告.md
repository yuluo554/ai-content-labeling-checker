## 三、做得好的部分（迭代中不要破坏）

1. **规则 status 门控与指纹门**：`pending` 绝不进判定；规则文件 sha256 由 `registry.json` 登记、加载器校验，不一致 exit 3。
2. **`not_assessed` 语义**：全 pending / 无适用规则 → `not_assessed`，不冒充 `compliant`；`skipped` ≠ `fail`。
3. **退出码契约**：0/1/2/3 四码齐备且被测试逐码锁定；批量 scan 的"失败件"不改变退出码、单列不静默吞。
4. **基准与测试共用同一实现**：`benchmark/cases.py` 单一对账口径；期望值从注入点推出、合规取值从规则库派生，不抄引擎。
5. **解析通路显式降级**：读不到载荷 → `unknown` + 原因码，绝不臆测。
6. **报告确定性**：`generate_at` 钉死；XLSX 内部时间戳钉死；`evidence.json` 带报告 sha256；我们复跑两轮五文件全同。
7. **AST 架构守门**：核心层零第三方、CLI 顶层不 import GUI、GUI 服务层零 Qt 且零判定。
8. **打包白名单 + 冻结态验伪**：只内嵌 6 个数据子目录；`verify_dist` 断言数据目录落在 dist 之内且 `frozen=True`。
9. **脱敏审计入仓**：四步 + 产物字节扫描 + 阳性/阴性自检；输出不回显敏感串；提交邮箱全 noreply。
10. **发布物干净**：CLI zip 无 Qt；GUI zip 无 jedi/IPython/PIL/numpy 等无关重件；无 `_private`。
11. **CI 守门测试**：workflow YAML 真解析（防"非法 YAML 不建 job"假活）、`fetch-depth: 0` 防历史空验、dev extra 防 pyyaml 缺席静默 skip。
12. **演示素材离屏渲染真实界面**；README 有下载节 + 截图 + 基准表；技术报告七章。

## 四、缺陷清单

### D1（P1）Python 3.8 已 EOL，且被 CI 守门测试硬编码

**现象**
- `pyproject.toml:10`：`requires-python = ">=3.8"`。
- `.github/workflows/ci.yml`：test 矩阵 `windows 3.8 / windows 3.12 / ubuntu 3.12`；cli-smoke `windows 3.8 / ubuntu 3.12`；packaging-guard `windows 3.8 / ubuntu 3.12`。
- `pyproject.toml:40-48`：3.8 上 `PySide6<=6.6.3.1`、`pyinstaller>=5.13,<6`；3.9+ 上 `PySide6>=6.6,<6.8`、`pyinstaller>=6`。
- `tests/test_guard_ci.py:109-110` **硬编码** `assert "3.8" in versions`——抬下限会打挂该测试。
- `plan/06-决策记录.md` D16/D39、`plan/03` §四都记录了"3.8 只守 Windows"与"GUI≈158 MB/CLI≈13 MB"。

**证据（实测/外部数据）**
- Python 3.8 安全支持止于 **2024-10-07**；3.9 止于 2025-10-31；3.10 止于 2026-10-01；3.11 至 2027-10-31；3.12 至 2028-10-31（endoflife.date/python）。
- **实测**：py3.12.10 + PySide6 **6.12.0** + openpyxl → `438 passed`，退出 0（`<6.8` 上限并非必要）。
- **实测**：py3.12 + PyInstaller **6.22.3** + PySide6 6.12.0 在 `git archive` 临时副本中 `python -m tools.build_exe --clean` → 构建成功 + `verify_dist` 两 exe 全通过（`data_dir` 落 dist 内、`frozen=True`、rules=27）。
- 发布 zip 内是 `python312.dll`（py3.12 构建），说明"打包路径"本身早已现代化；过时的是**声明下限与 CI 矩阵**。

**修复方向（见决策 D-1）**
- 抬 `requires-python` 到 3.12（或 3.11）；CI 去掉 3.8 作业；`gui` 改 `PySide6>=6.12,<7`；`pkg` 统一 `pyinstaller>=6.22,<7`。
- 同步改 `tests/test_guard_ci.py` 的矩阵断言（**合法规格变更**，不得顺手删 `fetch-depth`/`[dev]` 等其他断言）。

### D2（P1）CI 从不安装 `report` extra → XLSX 确定性测试每次都被 skip；主 test job 只跑 422/438

**现象**
- `.github/workflows/ci.yml` 全文件搜 `openpyxl`/`report`：**0 个安装步骤**（只有注释与"core-only 无 openpyxl 降级"的 cli-smoke 断言）。
- `tests/test_report.py:217` `test_xlsx_is_deterministic_even_without_timestamp` 用 `pytest.importorskip("openpyxl")` → 无 openpyxl 即 skip。
- 实测 dev-only 环境（模拟 test job 的 `.[dev]`）：`422 tests collected`、`421 passed, 2 skipped`；而全环境为 `438 passed`。差集 = `test_gui_tabs` 模块 16 项（gui-smoke 另有覆盖）+ `test_report` XLSX 1 项（**无任何 job 覆盖**）。
- 没有任何 CI 步骤断言各 job 的收集数；README 的「CI 8 job 全绿」无法区分"跑全了"与"skip 了"。

**修复方向（见决策 D-3）**
- test job 安装 `.[dev,report]`（或把 report 加进 dev），让 XLSX 测试真跑；`gui-smoke` 装 `.[dev,gui,report]` 并跑全量或至少 GUI+XLSX。
- 每个 pytest job 增加收集数对账步骤（如 `pytest tests --collect-only -q | tail -1` + 期望值）；在 `test_guard_ci.py` 增加"CI 必须安装 report extra"的接线断言（与现有 `test_ci_installs_dev_extras...` 同构）。

### D3（P2）CI 没有任何 job 构建/验收 exe；发布物可复现性只在本地

**现象**
- CI 5 类 job：test / cli-smoke / gui-smoke / packaging-guard；`packaging-guard` 只跑 `tests/test_packaging.py` 的**纯逻辑**（不跑 PyInstaller）。
- README 明说"真构建 exe 耗时长，不进 CI；本地用 `tools/build_exe.py`"。
- 发布 zip 由本机 py3.12/PyInstaller 6 构建；本地 `dist/` 与 Release 一致（17 MB CLI / 112 MB GUI 文件夹）。
- **实测**：py3.12 + PyInstaller 6.22.3 的构建只需要约 1 分钟量级，`build_exe` 自带 `verify_dist`，具备进 CI 的条件。

**修复方向**：增加一个 windows/py3.12 的 `package` job：`pip install -e ".[dev,gui,report,pkg]"` → `python -m tools.build_exe --clean` → `python tools/verify_package.py`。这样"发布物可复现"成为常驻门禁。
